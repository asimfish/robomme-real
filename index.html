Astra 直接控制 vs. Astra + 记忆 Harness

Setting

真机 setting · Franka 单臂 · Astra 零样本

对比条件

Baseline-1

Astra direct（直接控制）

配置与仿真 RoboMME-Plus 榜单上的 Embodied-Astra 一致：文本历史 + 每个相机最近 2 帧 RGB。

正文
Ours

Astra + Harness

本文方法。测试前冻结配置，测试期间不再调整。

正文
Baseline-2

Astra + 长上下文

均匀抽取 K 帧历史图像放进上下文，token 预算与 Ours 相当，回答"收益是不是只来自多给的图像"。只在 Plus 档跑，时间不够就不做。

补充材料 · 可选
dev 校准

Astra + Oracle 记忆

把真值记忆状态以文本交给 Astra，只在 dev 阶段用来检查执行难度是否合适，不进论文。

不报告
各组共用，唯一差别是记忆部分
Astra 版本与采样参数prompt 与任务指令move_eef 接口相机安全层轮数上限episode 卡片同一段演示录像操作员

Harness 只能处理同一路观测流，不能用额外传感器或真值信息。

目标

记对

Harness 是否让 Astra 在四类记忆上记对：数对次数、找对被盖住的目标、认对同一个物体、复现对路径。

归因

收益是否来自记忆：记忆决策正确率提升；而在记忆决策正确的试验里，两组的执行成功率接近。

难度曲线

从 Base 到 Plus，记忆负载增加时，Baseline-1 的成功率下降得比 Ours 多。

仿真与真机一致

真机上的提升与 RoboMME / RoboMME-Plus 仿真上的提升方向一致。

统一评估指标

成功率 SR 主指标
每条件 N=10，与 RoboMME 真机协议一致。初始摆放、目标、交换序列由 episode 卡片随机化。
记忆决策正确率
每个任务单独定义（见各任务卡片），并标出随机猜的概率。
平均完成时间 Time
总耗时 + 模型调用轮数。Ours 另报 harness 额外调用次数和 token。
安全性
拒绝目标次数、越界、急停次数。

仿真参考

4 个真机任务对应的 5 个仿真任务里，Astra 直接控制的成功率都不超过 30%，留给 harness 的提升空间大。

A

核心任务进度 · MDT = Memory-Dependent Task

四类记忆各一个任务，与 RoboMME 论文的 4 个真机任务同名、同映射。每个任务分 Base（对应 RoboMME）和 Plus（对应 RoboMME-Plus）两档。A 是场务，B 是控制台，见人工操作规程。

MDT1 计数 · 时间记忆

PutFruits对应仿真 BinFill

30%
仿真参考
Embodied-Astra
Prompt
BASEPut two apples and one lemon into the bin, then press the button to stop.
PLUSPut two apples, two lemons and one orange into the bin, then press the button to stop.

数量和种类由卡片决定。

场景
桌面 + 果篮（塑料水果）+ 深的不透明桶（相机看不到桶内数量）+ USB 按钮（按下时间戳自动记日志）
难度
BASE 对应 RoboMME
  • 要求 2–3 个，1–2 种
  • 没有人为干预
PLUS 对应 RoboMME-Plus
  • 要求 4–5 个，2–3 种
  • 一次人为干预：第 2 个放进桶后，人从桶里取走 1 个放回篮子
人工操作
  1. 每个 episode 前 A 按卡片往篮子里放水果（要求的数量 + 2 个干扰水果），清空桶。
  2. Plus 档：机器人把第 2 个水果放进桶、夹爪张开后，B 按暂停。
  3. A 从桶里取出卡片指定的水果，举在相机前停 2 秒，放回篮子，退出工作区。
  4. B 恢复运行。整个过程相机不停录。
配对方式
历史由机器人自己的动作产生，无法回放；两组按同一张卡片摆放，干预的时机和对象相同。
成功判定
按下按钮时，桶内每种水果的数量与要求完全一致。
记忆指标
按按钮时各类水果的计数误差之和；Plus 档另记干预后是否补放
失败模式
提前按多放干预后没补放没按抓取失败安全停机超时

Ops

人工操作

人工操作规程

人手动作只有五种：摆放、盖杯、滑动交换、拿起放回、点触节点。全部写在卡片上，按节拍执行，换人做出来也一样。

A场务
  • 按卡片摆放和复位
  • 做演示、做 MDT1 的干预
  • 每张卡片跑完后掀杯核对真值
B控制台
  • 开始 / 停止录制，启动 / 暂停 / 恢复试验
  • 机器人运动时全程手持急停
  • 记录结果，用参考帧检查复位
安全硬规则
  1. 人手进入工作区之前，机器人必须处于暂停或停在 home 不动，由 B 口头确认"可以进"。
  2. 演示阶段机器人停在 home，不运行模型。
  3. 机器人运动时，A 站在工作区外 1 m，B 手持急停。
  4. 暂停键：当前动作执行完就停住，之后的动作等恢复后再执行；相机不停录。

演示规范（MDT2–4 共用）

站位

A 站在机器人对面，从桌子远端伸手，身体不挡在相机和物体之间。

着装

不穿红、绿、蓝色衣物，戴纯色手套或袖套，避免和方块颜色混淆。

节奏

节拍器 60 BPM。盖杯 1 拍，交换 2 拍，动作之间停 1 拍。一段演示 15–25 秒。

出错

交换顺序错、杯子翻倒、方块露出：当场作废重录。两组都还没跑，不影响配对。

每张卡片的流程（视频类 MDT2–4）

  1. 1按卡片在网格垫上摆初始布局A
  2. 2机器人停在 home，开始录制B
  3. 3按卡片的节拍脚本做演示，结束后双手离开A
  4. 4停止录制，保存为本卡片的演示；抓拍一张最终布局作为参考帧B
  5. 5用这段演示跑第一组（按 ABBA 顺序决定先跑哪组）机器人
  6. 6按卡片答案把物体复位到最终布局；控制台把参考帧半透明叠在实时画面上，对齐后再继续A
  7. 7用同一段演示跑第二组机器人
  8. 8掀开全部杯子拍照，核对真值与卡片一致；不一致则这张卡片作废重做A

MDT1 的流程

  1. 1按卡片往篮子里放水果，清空桶A
  2. 2跑第一组；Plus 档在第 2 个水果放进桶后按暂停B
  3. 3Plus 档：从桶里取出指定水果，举在相机前停 2 秒，放回篮子，退出工作区A
  4. 4恢复运行，直到按按钮、超时或 give_up机器人
  5. 5清点桶内水果，记录结果；按同一张卡片复位，跑第二组A
单张卡片耗时（估算，11-09 实测后替换）分钟
视频类：摆放 2 + 演示 1 + 两组运行 2 × 8 + 复位 2 + 核对 1≈ 22

设计说明

一、实验总体目标

  • 四类记忆各一个任务。计数 / 物体永久性 / 指代 / 模仿，与 RoboMME 的四个 suite 对应，不再加扩展任务。
  • 按难度分两档。Base（对应 RoboMME）→ Plus（对应 RoboMME-Plus）。
  • 记忆必要性。只看最后一帧必须无法完成任务。手段包括不透明杯、深桶、外观相同的木块、不留痕的画笔。
  • 人手动作可复现。只用离散、按节拍执行的动作，不做连续滑动、挡板遮挡这类难以复现的操作。
  • 道具只用塑料、泡沫和木头，不用玻璃仪器。Astra 评测论文（arXiv 2609.24170 §5）报告真机上反复出现不安全动作并损坏设备；玻璃也易碎。
  • 没有训练 / 测试划分。Astra 零样本，没有训练集。调试只用 dev 卡片，测试卡片只用于评测，测试前冻结 prompt 和 harness 配置。

记忆难度条件 对应原模板的"泛化条件"；每个任务 Base 取 x.1，Plus 取 x.2

二、覆盖范围

真机覆盖四类记忆的代表任务，完整能力评测在仿真中完成。论文里按这个口径写，不写成"真机验证了 RoboMME-Plus 的各项能力"。

RoboMME-Plus 的难度变化真机说明
演示历史（分批遮盖、交换）覆盖MDT2、MDT3
集合型目标覆盖MDT2 Plus："all containers hiding blue cubes"
外部事件更新记忆覆盖MDT1 Plus 的人为干预
演示与执行布局不同覆盖MDT4 Plus
记忆负载部分最多 5 个杯子、计数 5，低于仿真（最多 28 个杯子）
挡板遮挡不做需要第三人同步操作，难以复现
物体或目标在动、按时机操作不做Astra 每轮要等一次模型调用，是底层控制的限制，不是记忆的限制
短暂线索、事件 / 顺序参照不做PickHighlight、VideoPlaceButton / Order 只在仿真评测
工具变化、精细插入不做Astra 精细操作弱（RoboDojo 精度项 4%）
少样本设置待定看仿真是否报 few-shot 结果

三、实验流程

  1. 1

    搭场景和安全层

    安全层两组共用，写进论文附录。目标越界时拒绝执行，把错误返回给模型，机器人不动。

    约束建议值（用 dev 卡片标定）超限处理
    工作空间桌面上方长方体；z 下限 = 桌面 + 1.5 cm（画笔任务按笔尖偏移另设）拒绝，返回错误
    单步位移 / 转角≤ 20 cm / ≤ 45°拒绝，返回错误
    笛卡尔速度≤ 0.15 m/s规划器限速
    碰撞阈值调低 libfranka collision behavior 阈值，用阻抗控制触发反射后停止
    夹爪力≤ 20 N限幅
    暂停键当前动作执行完就停住，相机不停录供人为干预使用
    急停B 全程手持计为安全停机，该次失败
    轮数 / 时间上限如 60 轮或 20 分钟，按 dev 校准超时失败
  2. 2

    生成 episode 卡片

    用固定随机种子，每个任务每个难度生成 10 张测试卡片 + 3 张 dev 卡片。卡片写明物体网格坐标、颜色 / 种类、要求数量、节拍脚本、目标和答案。桌面铺 5 cm 网格的打印垫，按坐标摆放。下面是一张示例卡片。

  3. 3

    dev 试跑和演示练习

    A 用节拍器把每个任务的演示练熟。每个任务每组跑 3 张 dev 卡片，测单张耗时；再用 Oracle 记忆跑一次，如果 Base 档成功率低于 30%，先降低执行难度（放大物体、加大间距、放宽容差），再冻结配置。调整过程写进附录。

  4. 4

    正式评测

    • 按人工操作规程执行，视频类和 MDT1 各有一套流程。
    • 顺序平衡：同一张卡片的两组同一天连续跑；卡片之间按 ABBA 交替先后，抵消光照、设备、API 随时间的漂移。
    • 重跑规则：演示出错当场重录；设备、网络、API 报错可以重跑同一张卡片并记录次数；策略导致的安全停机、超时、give_up 一律计失败，不重跑。
    • 记录：每次试验一个 run ID，保存全部相机流、每轮模型输入输出、harness 记忆状态、工具调用及接受 / 拒绝、末端轨迹、按钮时间戳、暂停区间、安全事件、耗时、轮数、token。
  5. 5

    判定

    能自动判的自动判（按钮日志、末端轨迹）。其余由 2 人看录像判定，录像不显示条件标签，有分歧时讨论决定。

四、对比实验设计

对比任务回答的问题放在
Ours vs Baseline-1MDT1–4 全部harness 是否提升真机成功率正文主表
Ours vs Baseline-2（长上下文）Plus 档收益是不是只来自多给的图像补充 · 可选
Harness 模块消融—各模块的贡献只在仿真做
离线探针 · 无历史

只给 Astra 最后一帧 + 指令，让它回答"选哪个杯子 / 哪块木块 / 已放几个"。正确率应接近随机猜，证明任务需要记忆。用已录的数据，不占机器人时间。

离线探针 · 记忆问答

在录好的演示上让 Baseline-1 和 Ours 回答记忆问题，不执行动作。可用几十个样本补充真机每格 10 次的统计量。

统计
每格报 x/10 和 Wilson 95% 置信区间；配对样本合并后做精确 McNemar 检验。不对单个任务的 10 次结果下显著性结论。
论文呈现
硬件布置 + 4 个任务图，标出每个任务需要记住的信息；真机成功率主表（行 = 任务 × 难度，列 = Baseline-1 / Ours，旁边放对应仿真数字）；失败分类堆叠柱状图；一次 rollout 的时间轴，对比 harness 记忆状态、真值和 Baseline-1 的出错点。
背景引用
RoboMME 论文的真机结果为 π0.5 4/40、GroundSG+QwenVL 19/40、FrameSamp+Modul 25/40。那些是训练过的 VLA，硬件和道具也不同，不放进同一张表比较。
